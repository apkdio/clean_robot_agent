# 意图分类数据集与标注口径

本目录的数据用于训练 `tools/intent_router.py` 的四分类头（`Linear(1024→4)`），
训练脚本见 `intent_classifier_training/train_intent_classifier.py`。

数据文件：`intent_dataset.jsonl`，每行一个样本：

| 字段 | 说明 |
|---|---|
| `text` | 用户**单句**原文（不做任何加工，保持口语） |
| `label` | `robot` / `other` / `casual` / `unknown`（四类，见下） |
| `source` | 样本来源：`base`（历史 491 条）/ `multiturn_real`（真实会话追问）/ `curated`（按口径人工补）/ `hard_negative`（边界反例） |

> **这个分类头是单句的、无状态的**：只看当前一句，不看上文。多轮里"指代在上文"的情形
> 由 `tools/agent.py` 的承接/改写层处理（见 `notes/project_detail.md` ADR-19）。
> 因此标注时**不要**根据上文改写这句的意思，也不要把它标成"上文那个话题"——只标
> **这句话本身能让人看出什么**。

## 四类口径（2026-09-23 修订）

判定顺序：先看这句话的**主题能不能确定**，再看它是**诉求**还是**对话性回应**。

| 类别 | 定义 | 判据 | 例子 |
|---|---|---|---|
| `robot` | 本身足以判定是**扫地机器人域内**的问题/诉求 | 含域内实体（滤网、边刷、电池、型号、保修……）或域内动作（清洗、更换、维修、连接 APP）；**无主语但现象或诉求完整**也算（2026-10-09 定） | 「滤网多久换一次」「有延保服务吗」「机器维修」「找不到充电座怎么办」「频繁碰撞家具」 |
| `other` | 本身足以判定是**域外**问题（主题明确，只是不在本域） | 主题是别的东西/别的问题域 | 「豆浆机怎么清洗」「今天天气怎么样」「那你们有飞机卖吗」 |
| `casual` | 不含待解决诉求的**对话性内容** | 寒暄、闲聊、情绪、道谢、确认收尾、对助手本身的元话语 | 「你好」「讲个笑话」「好的谢谢」「那就这款了」 |
| ↳ 补充 | **情绪 / 投诉 / 施压**句，即使句里附带域内动作，只要主体是情绪或施压，也归 `casual` | 「我要投诉你们」「烦死了」「你们得给我个说法」「最好是能给我修好，不然我肯定投诉你们」（2026-09-30 定）| 同左 |
| `unknown` | **句子本身不足以判定它指向什么**——缺指代对象或话题，必须靠上文才能定位 | ① 极短且缺主体（「划算吗」「买哪个」）② 含指代词/省略且同句无线索（「那这个怎么清洗」「那你们的品牌呢」）③ 承接型追问：句式完整但话题靠上文（「那这个电流现象影响大吗」「整体的价格分布情况呢？」）④ **只有域内实词、既无诉求也无现象描述**（「充电座」「边刷」「滤网」「耗材」「脱困」；2026-10-09 定） | 同左 |

### 几个最容易标错的地方

1. **短 ≠ unknown**。短的域内句仍是 `robot`：「保修期多久」「维修要多久」。
   反过来，**长也不等于 robot**：「整体的价格分布情况呢？」是 11 个字的承接型追问 → `unknown`。
   旧数据里 `unknown` 全是 4 字左右的短语（最长 6 字），所以分类头学到的其实是"短 = unknown"，
   长句承接型追问在结构上不可能被判成 `unknown`——这正是 2026-09-23 修订口径要修的东西。
2. **有指代词 ≠ unknown**。要看指代对象是否影响主题判定：
   「那你们有飞机卖吗」有指代但主题明确（卖飞机）→ `other`；
   「那这个怎么清洗」指代对象未知（清洗什么？）→ `unknown`。
3. **元话语归 `casual`（已知次优）**。像「我还没描述啥问题呢你就知道了？」这种对助手本身的
   质疑/追问，理想处置是**解释澄清**（说明推断依据），现有四类里没有对应出口 →
   暂按 `casual` 标注（走闲聊回复，最不伤），等引入第 5 类或专门的澄清出口再改。
   这一条在数据里用 `source=curated` 标注，便于后续按来源重标。
4. **纯泛化服务问项 → `unknown`**。「多少钱」「有现货吗」「能开发票吗」「能修吗」「可以退吗」
   「在哪里买」「什么时候到」这类只有服务意图、**句内没有任何域内实体或动作**的句子 -> `unknown`
   （与 `test_scripts/unit/test_intent.py` 的既有期望一致）。
   反过来，一旦句内出现域内实体或动作（滤网、边刷、尘盒、水箱、电池、耗材、保修、维修、
   售后、APP、回充……）就是 `robot`：「保修期多久」「滤网怎么拆」「换电池多少钱」。
   两类样本都用 `source=hard_negative` 标出，它们是这条口径线的两侧反例。
   操作类动作同样算域内动作（配网、建图、分区、回充、定时清扫、升级固件）——2026-10-12 补了这一族；
   **口语前缀不改变标签**：「那你说说，怎么使用机器人」仍是 `robot`。对应的边界是只丢一个实词的
   「配网」「建图」→ `unknown`（与上一条同一条线）。
5. **没有主语不等于判不了域内**（2026-10-09 定）。分界看**诉求/现象是否完整**：
   只丢一个实词（「充电座」「边刷磨损」）→ `unknown`（信息不足，走软引导 + RAG 兜底）；
   本身就是完整的现象或诉求（「找不到充电座怎么办」「频繁碰撞家具」）→ **`robot` 且要学成高置信**。
   该批样本：前者 `source=hard_negative`，后者 `source=curated`。（起因：实测这类无主语句
   被判成**高置信 `other`** → 直接硬拒答，而现有低置信降级只看 margin、救不到。
   2026-10-18 起下游已加一层确定性兜底：判成 `other` 但能命中知识域词表就不再拒答（ADR-35）——
   标签口径不变，这批样本仍要按"该判 `robot`"来训。）

## 与下游处置的对应关系（tools/agent.py）

| 标签 | 出口 |
|---|---|
| `robot` | 域内正常回答（追问承接 / 型号 / 系列 / SOP / RAG，无软引导语） |
| `unknown` | 同上 **+ 软引导语 + 强制按上文改写后检索**（「我猜你想问扫地机器人相关的问题吧」） |
| `other` | 拒答；**命中知识域词表则不拒答、走检索**（ADR-35）；低置信（`intent.low_conf_margin`）且上文有可承接话题 → 降级为 `unknown` |
| `casual` | 闲聊回复 |

**安全承接不看这四类标签**：危险告警在窗口内时，除"高置信 robot"（`intent.high_conf_margin`）
外一律先承接——见 `tools/agent.py` 的 S2-a 与 `config/context_template.yaml`。

## 改动数据的约定

- 新增样本必须带 `source`；**不要**为了平衡类别去改已有样本的标签。
- **训练集不得与评测集/单测逐字重叠**（`test_scripts/eval/test_intent_eval.py` 会检查，重叠即泄漏，
  评测分数会虚高）。要补某一族时**换句子补"同族不同句"**，别把评测集里的原句搬进来。
- 改完先跑 `intent_classifier_training/train_intent_classifier.py`（会打印各类 F1 与
  按来源分组的准确率），再用 `test_scripts/` 的上下文评测确认线上行为没退化。
- **别指望目标句一定进训练集**：`multiturn_real` 按约定全部划入测试集，其余类别按 20% 分层抽样，
  想修的某一句可能正好被切走（2026-10-12 就遇到两条目标句被切进测试集）。所以补样本要补**同族若干句**、
  靠泛化翻面，复验看的是族而不是那一句。
- **负例别与正例同形**：要教「APP／下载」属域内动作时，别配「抖音 APP 在哪里下载」这类同形反例——
  它会把正向模式整片带走（2026-10-12 实测「官方APP在哪里下载」被带成 `other`）。反例要换形状
  （「抖音怎么保存别人的视频」「微信怎么改群备注」）。
- **补一侧要同时看对面边界**：这颗线性头在 ~850 条上已到容量边界（`notes/OPTIMIZATION_ROADMAP.md` 同一结论），
  补一族正例常把邻族边界整体带翻。2026-10-12 实测：补「前缀 + 操作类」正例修好了目标句，却把
  「你是公机器人还是母机器人」（闲聊）带成 `robot`；补闲聊样本修回来，又把「那你们的品牌呢」「要报修」
  这两条**必过**用例带成 `casual`（主链路 `casual` 直接走闲聊、无承接，属真回归）。
  所以改完要跑**行为轨 + 一份覆盖两侧边界的探针**，按「必过用例不翻 + 目标句修好」取版本，别只盯目标句。
- `data/bgm_model/` 下的权重是训练产物（已 gitignore），重训后需重启服务生效。
