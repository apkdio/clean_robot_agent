# 意图分类数据集与标注口径

本目录的数据用于训练 `tools/intent_router.py` 的四分类头（`Linear(1024→4)`），
训练脚本见 `intent_classifier_training/train_intent_classifier.py`。

数据文件：`intent_dataset.jsonl`，每行一个样本：

| 字段 | 说明 |
|---|---|
| `text` | 用户**单句**原文（不做任何加工，保持口语） |
| `label` | `robot` / `other` / `casual` / `unknown`（四类，见下） |
| `source` | 样本来源：`base`（历史 491 条）/ `multiturn_real`（真实会话追问）/ `curated`（按口径人工补）/ `hard_negative`（边界反例） |

> **这个分类头是单句的、无状态的**：只看当前一句，不看上文。多轮里"指代在上文"的情形
> 由 `tools/agent.py` 的承接/改写层处理（见 `notes/project_detail.md` ADR-19）。
> 因此标注时**不要**根据上文改写这句的意思，也不要把它标成"上文那个话题"——只标
> **这句话本身能让人看出什么**。

## 四类口径（2026-09-23 修订）

判定顺序：先看这句话的**主题能不能确定**，再看它是**诉求**还是**对话性回应**。

| 类别 | 定义 | 判据 | 例子 |
|---|---|---|---|
| `robot` | 本身足以判定是**扫地机器人域内**的问题/诉求 | 含域内实体（滤网、边刷、电池、型号、保修……）或域内动作（清洗、更换、维修、连接 APP） | 「滤网多久换一次」「有延保服务吗」「机器维修」 |
| `other` | 本身足以判定是**域外**问题（主题明确，只是不在本域） | 主题是别的东西/别的问题域 | 「豆浆机怎么清洗」「今天天气怎么样」「那你们有飞机卖吗」 |
| `casual` | 不含待解决诉求的**对话性内容** | 寒暄、闲聊、情绪、道谢、确认收尾、对助手本身的元话语 | 「你好」「讲个笑话」「好的谢谢」「那就这款了」 |
| `unknown` | **句子本身不足以判定它指向什么**——缺指代对象或话题，必须靠上文才能定位 | ① 极短且缺主体（「划算吗」「买哪个」）② 含指代词/省略且同句无线索（「那这个怎么清洗」「那你们的品牌呢」）③ 承接型追问：句式完整但话题靠上文（「那这个电流现象影响大吗」「整体的价格分布情况呢？」） | 同左 |

### 三个最容易标错的地方

1. **短 ≠ unknown**。短的域内句仍是 `robot`：「保修期多久」「维修要多久」。
   反过来，**长也不等于 robot**：「整体的价格分布情况呢？」是 11 个字的承接型追问 → `unknown`。
   旧数据里 `unknown` 全是 4 字左右的短语（最长 6 字），所以分类头学到的其实是"短 = unknown"，
   长句承接型追问在结构上不可能被判成 `unknown`——这正是 2026-09-23 修订口径要修的东西。
2. **有指代词 ≠ unknown**。要看指代对象是否影响主题判定：
   「那你们有飞机卖吗」有指代但主题明确（卖飞机）→ `other`；
   「那这个怎么清洗」指代对象未知（清洗什么？）→ `unknown`。
3. **元话语归 `casual`（已知次优）**。像「我还没描述啥问题呢你就知道了？」这种对助手本身的
   质疑/追问，理想处置是**解释澄清**（说明推断依据），现有四类里没有对应出口 →
   暂按 `casual` 标注（走闲聊回复，最不伤），等引入第 5 类或专门的澄清出口再改。
   这一条在数据里用 `source=curated` 标注，便于后续按来源重标。
4. **纯泛化服务问项 → `unknown`**。「多少钱」「有现货吗」「能开发票吗」「能修吗」「可以退吗」
   「在哪里买」「什么时候到」这类只有服务意图、**句内没有任何域内实体或动作**的句子 -> `unknown`
   （与 `test_scripts/test_intent.py` 的既有期望一致）。
   反过来，一旦句内出现域内实体或动作（滤网、边刷、尘盒、水箱、电池、耗材、保修、维修、
   售后、APP、回充……）就是 `robot`：「保修期多久」「滤网怎么拆」「换电池多少钱」。
   两类样本都用 `source=hard_negative` 标出，它们是这条口径线的两侧反例。

## 与下游处置的对应关系（tools/agent.py）

| 标签 | 出口 |
|---|---|
| `robot` | 域内正常回答（追问承接 / 型号 / 系列 / SOP / RAG，无软引导语） |
| `unknown` | 同上 **+ 软引导语 + 强制按上文改写后检索**（「我猜你想问扫地机器人相关的问题吧」） |
| `other` | 拒答；低置信（`intent.low_conf_margin`）且上文有可承接话题 → 降级为 `unknown` |
| `casual` | 闲聊回复 |

**安全承接不看这四类标签**：危险告警在窗口内时，除"高置信 robot"（`intent.high_conf_margin`）
外一律先承接——见 `tools/agent.py` 的 S2-a 与 `config/context_template.yaml`。

## 改动数据的约定

- 新增样本必须带 `source`；**不要**为了平衡类别去改已有样本的标签。
- 改完先跑 `intent_classifier_training/train_intent_classifier.py`（会打印各类 F1 与
  按来源分组的准确率），再用 `test_scripts/` 的上下文评测确认线上行为没退化。
- `data/bgm_model/` 下的权重是训练产物（已 gitignore），重训后需重启服务生效。
